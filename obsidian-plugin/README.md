# ОРД Tracker Sync — плагин Obsidian

Синхронизирует документы ОРД (заметки Obsidian) с таск-трекером: заметка ↔ задача.
Разделение ролей — Obsidian владеет содержимым и свойствами `theme`/`type`/`links`,
трекер владеет статусом/стадией/сроками/связями (приходят обратно как read-only
свойства). Подробности — в корневом `PLAN.md`.

## Сборка

```bash
cd obsidian-plugin
npm install
npm run build       # → main.js (production)
# или npm run dev   # watch-режим
```

## Установка в хранилище

Скопируйте `manifest.json`, `main.js` (и `styles.css`, если появится) в
`<vault>/.obsidian/plugins/ord-tracker-sync/`, затем включите плагин в
Настройки → Сторонние плагины.

Для разработки удобно собирать прямо в папку плагина vault'а (симлинк или
`outfile` в `esbuild.config.mjs`).

## Настройка

1. В трекере: **Настройки пространства → Синхронизация с Obsidian** — создайте
   токен, скопируйте секрет.
2. В плагине (Настройки → ОРД Tracker Sync): укажите **URL сервера**, вставьте
   **токен**, при желании ограничьте **папку** документов ОРД.

## Свойства заметки (Properties)

```yaml
---
theme: parolnaya-politika      # slug темы (проекта) в трекере — ОБЯЗАТЕЛЕН
type: [инструкция, ПДн]        # → метки задачи
links:                         # → исходящие связи (комплектность)
  - "[[Приказ об утверждении парольной политики]]"
# ↓ ниже трекер пишет сам (read-only), руками не трогать:
tracker_id: …
status: …       # not_started | in_progress | done
stage: …        # стадия (колонка доски)
due: …
review: …
completed: …
priority: …
assignee: …
tracker_url: …
tracker_updated: …
---
```

Заметка без свойства `theme` плагином игнорируется.

## Команды

- **Синхронизировать текущую заметку**
- **Синхронизировать все документы ОРД (со свойством theme)** — первичная загрузка
- **Открыть карточку в трекере**

## Как работает синхронизация

- Изменение заметки (`modify`/`create`/`rename`) → `POST /api/obsidian/upsert`.
  Отправляются только «входные» поля; тело документа не передаётся.
- Анти-эхо: плагин шлёт изменение, только если изменились входные свойства, —
  обратная запись трекер-полей не вызывает повторной отправки.
- Удаление заметки → `POST /api/obsidian/delete` (мягкая архивация задачи).
- Статусы из трекера подтягиваются опросом `GET /api/obsidian/changes?since=…`
  (интервал настраивается). SSE-эндпоинт `/api/obsidian/stream` также доступен.
